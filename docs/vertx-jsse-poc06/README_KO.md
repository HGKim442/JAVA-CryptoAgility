# PoC06 — Java TLS/JSSE 암호 정책 전환 일관성 검증

> **공개용 연구 체크포인트 — 세부 구현 자료 비공개**
>
> 기준일: 2026-11-06 · 상태: 통제된 실험 범위에서 검증 종료

## 연구 목적

원 과제 「Java JCA/JCE 암호민첩성의 보안성 분석」의 PoC06(정책 확인 시점과 암호 실행 시점의 불일치)을 공개 Java 네트워크 소프트웨어의 TLS/JSSE 설정 변경 환경에 확장하여 검토하였다.

연구 질문은 **설정 갱신이 완료되었다고 통지된 후 새로 시작하는 연결의 실제 보안 동작이 승인된 정책과 일치하는가**이다. 하이브리드 PQC 전환 상황에서 정책 효력 시점의 정의와 검증 필요성을 살펴보았다.

## 실험 방법과 진행 상태

- 원본 공개 소프트웨어와 연구용 격리 수정본을 **동일 조건**에서 비교하였다.
- 단일 갱신, 순차 갱신, 갱신 이후 병렬 연결 등 **통제된 실험**을 실시하였다.
- 연구용 수정본의 컴파일과 정해진 비교 대조군 검증을 완료하였다.
- 2026-11-06 최종 재검증에서 정해진 검증 기준이 통과되었다.
- 테스트 결과와 판단 근거는 지도교수·연구실 내부 문서 및 비공개 증거로 별도 보관한다.

**해석의 한계:** 위 결과는 지정된 테스트 구성에서의 기능 검증이다. 모든 Java TLS 엔진, Provider, 인증서 옵션, SNI·ALPN, 운영 환경의 원자성이나 보안성을 증명하지 않는다. 실제 공개 소프트웨어에 수정 사항이 반영되었다는 의미도 아니다.

## 원 과제와의 관계

| 항목 | 본 사례의 역할 |
|---|---|
| PoC06 | 암호 정책 변경과 실제 연결 동작 사이의 일관성 검토 |
| P2 | 전환 상태 및 정책 효력 시점 보호에 대한 제한된 검증 근거 |
| E1 | 기존 구현과 연구용 개선 접근의 제한된 기능 비교 |
| E2 | TLS의 하이브리드 PQC 정책 적용에 대한 확장 사례 |

이 사례는 원 과제의 **JCA/JCE 요청별 Cipher·KEM·Provider 경로 전체를 대체하지 않는다.** 또한 원 계획서의 V0/V1/V2 3개 구현 전체 비교가 완료되었다는 뜻은 아니다.

## 공개 범위 및 보안 검토

본 문서에는 공개 전 검토가 필요한 구체적 결함 재현 절차, 영향 버전 범위, 소스 위치, 패치, 원시 로그, 개인 환경 경로를 포함하지 않았다. 관련 자료는 비공개로 관리하며, 공개 여부는 지도교수·연구실 검토 및 프로젝트 담당자와의 조율 후 결정한다.

보안 관련 제보가 필요한 경우에는 프로젝트의 **비공개 취약점 신고 절차**를 따른다. 공개 GitHub 이슈·Pull Request로 미공개 취약점의 상세 재현 코드를 제출하지 않는다.
