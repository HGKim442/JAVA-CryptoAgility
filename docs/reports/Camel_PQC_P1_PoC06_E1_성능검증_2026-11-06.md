# Apache Camel P1·PoC06 E1 — 기능·반복성·성능 검증 체크포인트

**작성/관측일:** 2026-11-06 (KST)
**대상:** 공개 배포 `org.apache.camel:camel-pqc:4.22.0` (수정 없음)
**성격:** 사용자가 제공한 WSL 실행 출력에 대한 요약·해석. 원시 CSV는 사용자의 WSL `reports/normal_timing_20261106T091555Z_4009/`에 있으며, 이 문서 작성 환경에서 원시 CSV 파일을 직접 수집·재실행한 것은 아님.

## 1. 기존 기능 및 안정성 검증과의 연결

- V0(기존 호출): `HQC` 또는 존재하지 않는 KEM 요청을 캐시된 ML-KEM 생성기로 처리한 사례 관측.
- V1(헤더 허용목록): 유효하지 않은 요청은 막았지만 `HQC` 요청은 통과하여 ML-KEM으로 수행됨.
- V2(사전 허용목록 + 실제 JCA KeyGenerator 알고리즘/Provider 일치성 검사): 시험한 불일치 요청을 거부함.
- `KYBER`는 Camel 4.22.0 내부에서 `ML-KEM` 별칭이므로 다른 KEM 불일치 사례로 집계하지 않음.
- 12개 통제 조건의 기대 판정이 독립 JVM 10회에서 모두 일치: 120/120. 불일치 실행 3건/실행 × 10회 = 30건 **반복 관측**(서로 다른 결함 30개를 뜻하지 않음).
- 이 비교는 P1·PoC06의 **순차 단일 요인** 검증이며, 정책·키 버전 변경의 동시성 P2 및 하이브리드 E2의 완전한 보안성 검증이 아님.

## 2. 성능 실험 방법 (패키지 소스 확인)

- 환경: Eclipse Temurin JDK `25.0.5+8-LTS`, Maven `3.9.12`; 컴파일 `--release 21`. WSL 한 호스트에서 5개 독립 JVM.
- 정상 요청: 요청 KEM `MLKEM`, 고정 길이 짧은 메시지, ML-KEM-768 + AES-GCM(256비트 키). 모든 V0/V1/V2에서 정상 암복호화의 결과 일치 검증.
- JVM별 세 구현에 동일한 종류의 `PQCDataFormat`을 준비하고, 각 모드당 120회 예열 후 **300회 정상 암복호화** 측정. 총 5 × 3 × 300 = 4,500회 측정 기록.
- 측정 순서는 시드 기반 회전·역순으로 섞음. 각 모드는 동일 JVM 내에서 번갈아 실행됨.
- 정책 검사만의 벤치마크: 모드별 35배치 예열 후 120배치, 배치당 10,000회 정상 허용 확인. 하나의 JVM에서 모드별 120만 호출, 전체 5 JVM 1,800만 회의 호출을 계측. `MLKEM`과 `KYBER`(동일 ML-KEM 별칭)를 교대 사용.
- `System.nanoTime()` 기반 탐색적 측정. JMH/CPU affinity/고정 CPU 주파수/GC 동작 분리/실서비스 지연 측정은 아님. **마이크로벤치마크에서 JVM JIT 최적화와 배치 처리 영향이 있을 수 있음.**

## 4. E1 결과의 허용되는 주장 및 금지할 주장

**허용:** “실제 Camel 4.22.0 배포본에서 헤더 KEM 선택과 캐시된 구현의 불일치를 재현하고, 외부 P1 일치성 검사가 통제된 불일치 요청을 거부함을 확인했다. 10 JVM 반복 기능 시험과 5 JVM 정상 요청 비용 시험에서 결과가 일치했고, 후자에서 명확한 왕복 지연 저하는 관측되지 않았다.”

**금지:** “신규 미공개 취약점 발견/공식 패치 완료”, “P2의 동시성·키 교체 안전성 입증”, “V2 성능 저하 없음이 통계적으로 증명”, “프로덕션 오버헤드는 정확히 0.07%”, “허용된 Provider 이름 검사만으로 신뢰성 보장”.

Camel 현재 개발 브랜치의 KeyGenerator 생성 경로가 배포 4.22.0과 달라진 사실을 별도 확인했으므로, 최신 릴리스까지 동일 결함이 유지된다고 단정하지 않음.
