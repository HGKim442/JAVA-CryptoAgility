# Java JCA/JCE 암호민첩성: P1·PoC06 E1 연구 체크포인트

> **공개용 요약 (2026-11-06)**
> 연구용 통제 실험 기록입니다. 특정 제품의 보안 취약점 신고, CVE 보고, 공식 패치 또는 운영환경 안전성 인증을 의미하지 않습니다.

## 연구 목적

암호민첩성(Cryptographic Agility)에서 **정책상 허용된 암호 알고리즘**과 **실제 JCA/JCE 실행 경로에서 선택된 알고리즘**이 일치하는지 검증합니다. 단순한 알고리즘 문자열 허용목록만으로는 해당 일치성을 보장할 수 있는지, 추가적인 실행 시점 대조가 어떤 차이를 만드는지를 확인하는 실험입니다.

- **PoC06:** 요청별 암호 설정과 실행 결과의 일치성 문제
- **P1:** 요청된 암호 선택과 유효 실행 구현의 일치성을 요구하는 검사
- **E1:** V0(기준선), V1(문자열 허용목록), V2(허용목록 + 실행 구현 일치성)의 동일 정상/비정상 조건 비교

## 재현 및 검증 현황

- Java 기반 공개 PQC 라이브러리를 이용한 **제어된, 순차적** 실험에서 요청 암호 구성과 실행 알고리즘이 불일치하는 사례를 관측했습니다.
- V1 허용목록만 검사하는 구성에서는 이 유형의 불일치가 허용될 수 있었습니다.
- V2 실행 일치성 검사는 테스트한 불일치 요청을 거부했습니다. V2는 프로젝트의 공식 기능 또는 업스트림 패치가 아닌 **외부 연구용 검사**입니다.
- 동일 기능 12조건에서 기대 판정이 일치했고, **10개 독립 JVM에서 총 120/120 판정이 재현**됐습니다. 이는 독립 결함 120건이 아니라 동일 조건 반복입니다.
- 통제 실험 내 불일치 실행 성공은 3건/12조건으로 관측됐으며, 10 JVM에서는 30회 반복 관측입니다. 이것이 실제 공격 30건을 뜻하지는 않습니다.

## 정상 요청 처리 비용 (탐색적)

E1 정상 ML-KEM·AES-GCM 왕복에 대해 5개 독립 JVM, 모드별 각 300회씩, 총 **4,500개 왕복 측정치**를 수집했습니다. 예열은 JVM별 각 모드 120회입니다. 다음은 **각 JVM 중앙값들의 중앙값**으로, 개별 측정치 전체의 중앙값이 아닙니다.

| 지표 | V0 | V1 | V2 |
|---|---:|---:|---:|
| 정상 처리 왕복 (μs) | 108.400 | 108.913 | 108.474 |
| 정책 검사만 수행 (ns/호출) | 1.229 | 2.402 | 31.565 |

- JVM별 V2−V0 정상 왕복 차이: **−0.49% ~ +0.60%**, JVM별 차이의 중앙값 **+0.07%**.
- 이 조건에서는 정상 왕복 처리에서 일관된 성능 저하가 관측되지 않았습니다. **통계적으로 동등하다는 증거나 운영서비스 오버헤드 수치는 아닙니다.**
- 정책 검사만의 나노초 단위 측정은 JIT 최적화와 배치 구조의 영향을 받는 탐색적 마이크로벤치마크입니다. 상대 증가율을 전체 암호화 지연 증가율로 해석하지 않습니다.

요약 집계는 [`SUMMARY_METRICS.csv`](SUMMARY_METRICS.csv)에 기록했습니다. 원시 CSV는 연구자의 로컬 검증 자료로 보관하며 이 저장소에 게시하지 않습니다.

## 결론과 한계

이번 통제 실험은 **알고리즘 허용 여부만 확인하는 것과 실제 선택된 암호 구현까지 검증하는 것은 다르다**는 점을 보여줍니다. 연구 기여는 일반적인 취약점 최초 발견 주장보다, 실제 JCA/JCE 실행 선택의 일치성 검증과 통제된 V0/V1/V2 비교에 있습니다.

이 결과는 동시 정책 변경, 키 버전 교체의 원자성, 임의 Provider 교체, 하이브리드 PQC 비밀 결합, 서비스 운영부하 또는 모든 라이브러리 버전에 대한 검증이 **아닙니다**. 외부 라이브러리 개발 브랜치에서는 구현이 변경된 정황이 있으므로 본 연구가 특정 최신 릴리스의 현재 취약성을 주장하지 않습니다.

다음 단계는 연구계획서의 **P2 — 정책 효력 시점(snapshot 허용 vs strict cutover), 정책 버전·키 버전과 요청의 연결성**입니다.
