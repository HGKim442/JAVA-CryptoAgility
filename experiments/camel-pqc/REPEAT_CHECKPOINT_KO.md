# E1/P1·PoC06 독립 JVM 반복 재현 체크포인트 (2026-11-06)

**검증 환경(사용자 실행 기록):** Windows WSL, Eclipse Temurin OpenJDK 25.0.5+8-LTS, Maven 3.9.12, Apache Camel 4.22.0 릴리스 JAR, 순차 동작.

**관측 로그:** `REPEAT=1 PASS`부터 `REPEAT=10 PASS`까지, 최종 `RESULT=10_INDEPENDENT_JVM_REPEATS_PASS`.

각 `PASS`는 그 JVM의 콘솔 출력에서 세 마커가 동시에 발견되었음을 의미한다.

- `EXPECTED_MATCH=12/12`: 미리 정의한 정상/거부/불일치 조건 12개 모두 기대 상태와 일치.
- `EFFECTIVE_KEM_MISMATCH_SUCCESSES=3`: V0(HQC, 잘못된 KEM 이름), V1(HQC)에서 메시지 헤더와 불일치하는 ML-KEM 실행이 성공.
- `RESULT=CONTROLLED_E1_P1_COMPARISON_PASS`: 위 비교 조건 만족.

따라서 10번의 독립 JVM에서 총 `120/120` 조건 일치와 `30`회의 *동일한 불일치 조건 반복 관측*을 확인했다. **30개 독립 취약점이나 통계적 공격 성공확률로 해석하지 않는다.**

초기 실험에는 요청 `HQC`와 미등록 KEM 헤더의 처리 문제가 있었고, 캐시 제거 대조군에서는 미등록 KEM이 실패해 캐시 재사용이 주요 원인임을 뒷받침했다. 캐시 없는 HQC 실패의 구체적인 원인은 별도 분리하지 않았다. 현재 Camel `main`의 코드가 4.22.0과 동일하지 않다는 사실도 기록한다. 원본 공개 프로젝트에 영향을 주는 전체 버전 범위와 공격자 모델은 아직 확인하지 않았다.

**현재 범위:** PoC06, P1, E1의 순차 실행 기능 비교 및 재현성. 동시 구성 변경의 P2, E2의 하이브리드 비밀 결합, 실제 운영환경 안전성 및 신규성은 미검증.

**다음 단계:** 정상 ML-KEM 요청의 V0/V1/V2 추가 비용을 동일 조건에서 분리 측정. 이 패키지의 타이밍 수치는 실행 이전이며, 현재 기록에 수치 결과는 포함하지 않는다.
